# Requisitos do DevJobs 2.0

- Localize e leia primeiro as fontes oficiais em `docs/referencias/`, `README.md` e os artefatos estruturais pertinentes.
- Classifique cada afirmação como requisito confirmado, decisão aprovada, pendência ou sem evidência. Não trate uma proposta de plano como aprovação.
- Preserve a numeração oficial dos RFs. Não invente, complete lacunas ou renumere requisitos.
- Mantenha a cadeia `RF → RN → Caso de Uso → Entidade → API → Tela → Teste → Diagrama` nas mudanças autorizadas.
- Quando faltar fonte ou decisão, descreva o limite seguro e peça aprovação humana antes de criar regra funcional.
- Em mudanças estruturais autorizadas, identifique e atualize a documentação e os diagramas afetados.
- Não faça commit, push, ação destrutiva ou mudança fora do escopo solicitado.
